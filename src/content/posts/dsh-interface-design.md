> 界面上让人「觉得顺」的东西，几乎都不是随手调出来的。它们是先被一个具体的问题逼到墙角，才长成现在这样。下面七处，都是先返工、才定型的。

## 先说清楚：这不是一套皮肤，是一次逐项对账

2026 年 10 月，我给 DSH 桌面端做了两套皮肤。深色叫极光 HUD，浅色叫日间炫彩。约束是自己定的：**全直角、保留霓虹渐变、不改布局、不改交互逻辑**，只通过 profile 注入样式，一行宿主源码都不碰。

听起来是在做视觉。真正花掉时间的是另一件事：**把界面上每个「本来就该这样」的细节，重新问一遍「为什么是这样」**。因为一旦要覆盖它，你没法靠感觉——你必须先量出它现在是几像素、为什么是几像素、改掉之后别处会不会塌。

这篇文章不讲功能，只讲七件具体的事。每件都对应一个真实踩过的坑。

## 一、圆角归零，但圆点必须留着

全直角是硬约束。真正难的不是「把所有圆角写 0」，而是**判断哪些圆角不能写 0**。

深色皮肤里 `border-radius: 0 !important` 出现 **71 次**，而 `border-radius: 50%` 只保留 3 处：开关滑块、状态圆点、头像。理由不是审美偏好，是功能：

- 圆角是「容器」的语法，直角告诉眼睛「这是一块结构」
- 圆形是「状态」的语法，圆点告诉眼睛「这是一个可以变的量」

把开关也直角化，看起来风格统一了，实际上把「可切换」这个语义抹掉了——用户得靠位置判断那是开关。所以全局归零必须配一份白名单，而白名单的判据是**语义**，不是大小。

这条在实现上还翻过一次车：通用圆角规则加上去之后，开关的**药丸容器**被压成了方块，只剩里面那个圆点在动，视觉上完全不像开关。

![开关修复前后：左侧药丸被通配圆角压成方块，右侧药丸与圆点还原](/images/dsh-ui-design/01-switch-before-after.webp)

> 左：修复前，药丸容器被通配规则压成方块。右：修复后。差别只有一处 `border-radius`，但「这东西能拨」的信息量完全不同。

## 二、渐变描边不能用 `border-image`

输入卡上有几个控件需要一圈彩色描边：`+` 按钮、`+ 技能`、模型触发器。第一版用 `border-image` 配四向渐变——看着对，量出来是错的：**四条边的粗细不一致**，因为 `border-image` 是按九宫格切片拉伸，斜向渐变的切片在四条边上的有效厚度不同。

改成 `::before` + `conic-gradient` + `mask`：

```css
/* 1–2px 彩环：内容盒排除法挖空中间，只留一圈 */
mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
mask-composite: exclude;
```

要点有三条，都是踩出来的：

1. **按钮自身边框必须清零**。否则 1px 实线边框叠在彩环内侧，视觉厚度变成 3px，而你以为写的是 2px。
2. **亚像素会咬人**。26px 高的控件落在半像素位置上时，mask 的顶边会多渲染约 0.5–0.6px，于是顶边看着比底边粗。修法是顶部单独补 1.5px。
3. **`background-image` 不能插值**。所以聚焦时不能让描边从 `linear-gradient` 切到 `conic-gradient`——那会瞬间跳变。做法是让同一张 conic 图常驻，静止态 `opacity` 压低、动画 `paused`，聚焦时只过渡 `opacity` 并 `running`。

![会话行：下方选中态有彩环，上方静置态没有](/images/dsh-ui-design/02-ring-idle.webp)

> 环只在选中/聚焦时出现。常驻一张图、只动 `opacity`，是为了让「出现」这件事可插值。

## 三、「关掉动效」比「加动效」更容易做错

皮肤有一个动效总闸。第一版是这么写的：

```css
/* 错的做法 */
html body.ah-reduce-motion * { animation-play-state: paused !important; }
```

逻辑上没错——暂停所有动画。实际效果是：**关掉动效后，设置弹窗和菜单直接消失了**。

原因在于入场动画的 `animation-fill-mode: both`。`both` 会把「第一帧」也应用上，而入场动画的第一帧是 `opacity: 0`。暂停之后，元素永久停在第一帧——也就是永久透明。

正确的做法是让元素**回落到基础样式**，而不是停在动画的某一帧：

```css
animation: none !important;
```

这条现在在深色皮肤里出现 **16 次**，每个动画块一份。同时保留 11 处 `@media (prefers-reduced-motion: reduce)` 媒体查询，让系统级偏好也能关。

经验是：**「暂停」和「取消」是两件事**。暂停保留当前帧，取消回到静态定义。做「可关闭的装饰动效」时，你要的是后者。

## 四、焦点环只能有一个

`:focus-visible` 写起来一行，铺开之后问题很具体：输入卡片本身是一个大盒子，里面还有一层 `contenteditable` 的输入区。全局焦点规则一加，就变成「输入框里套着一层输入框」——外面一圈、里面一圈，两个焦点环互相打架。

处理方式是**把焦点反馈上移一层**：卡内 `[role="textbox"]` 的 `outline` 清零，焦点态只留整张卡的描边。插件市场的搜索框同理——外层 wrapper 已经有边框，内层 `<input>` 就不要再吃全局焦点环；而且在日间皮肤里，还有一条 `[class*="searchInput"] input:focus-visible` 的提权规则会再次命中，所以那条也得排除掉。

同一族的问题还有两个：

- **hover 不该有位移**。文字按钮 hover 时上移 1–2px，在密集列表里就是整行在抖。现在 hover 只改颜色和亮度。
- **按压只缩 1.5% 或提亮**，不做位移。会话行、项目行这些 `role="treeitem"`、右侧标签 `role="tab"` 也不是 `<button>`，但同样要覆盖——不然一屏里有一半元素点了没反馈。

判据很朴素：**同一时刻，用户的眼睛只能盯住一个焦点环**。第二个出现的时候，就是在告诉他「你刚才点的东西」和「你现在要输入的东西」不是一回事——但通常它们就是同一件事。

## 五、半透明页签栏必须配模糊

有一类问题只在滚动时暴露：内容滚到顶部页签栏下面，透过半透明底色显出一条脏影子。原因是页签栏写了 `background: rgba(..., .78)`，但**没有背景模糊**——半透明不等于毛玻璃，它只是把下面的内容按透明度混进来。

补上 `backdrop-filter: blur(12px) saturate(1.2)`（浅色 14px）之后，滚动的内容变成真正的「背后」而不是「透过来的脏色」。

这条的教训是：**半透明是一种承诺**。你承诺「下面是另一层」，就必须让它看起来像另一层。只降透明度不加模糊，得到的是「颜色不对」而不是「层次」。

## 六、装饰层要给弹窗让路

皮肤在窗口上铺了一层网格和一条扫描线，用来做 HUD 气氛。问题是它们的 `z-index` 比 dialog 高，于是**弹窗上永远蒙着一层雾状纹理**，标题发虚。

修法用了一条 `:has()`：

```css
body:has([role="dialog"][aria-modal="true"]) #ah-frame,
body:has([role="dialog"][aria-modal="true"]) #ah-scan {
  opacity: 0;
  animation: none !important;
}
```

只要屏幕上有模态弹窗，装饰层就整体退场。这比调 `z-index` 更稳——调层级只是在争谁在上面，而「有弹窗时气氛让位」本来就是这条装饰的边界。

与之配套的还有一条：文本对比度。宿主给的占位符色在深色底上只有 **1.9:1**，几乎看不见。深色调到 `#8EA6BE`，浅色调到 `#5F7189`。装饰可以省，可读性不能。

## 七、三个药丸：写下去不生效的那些规则

三个药丸按钮（权限、计划模式、模型）是输入卡上信息密度最高的地方。它们要同时表达三件事：当前状态、可点击、可展开。

![输入卡的三个药丸：完全权限、计划模式、模型触发器](/images/dsh-ui-design/03-pill-shine.webp)

> 三个药丸、三种语义：橙红是权限等级，蓝是模式，深蓝是模型。颜色不是装饰，是分类。

这里的坑是**特异性**。皮肤自己写了 `[data-composer-card] button[class$="_primary"]:hover` 带 `!important`，特异性 0-4-1。后来想给按钮加一层扫光，新规则写下去**完全不生效**——因为特异性不够。解法不是再加 `!important`（两边都有，等于没加），而是带同样的 `[data-composer-card]` 前缀把特异性压到 0-4-3。

彩环本身的结构也值得记一下，因为它决定了后面能怎么改：`inset: -1px` 让它比按钮外扩 1px 露在边缘，`padding: 1px` 配合 `content-box` 把中间挖空，渐变里还特意留了两段 `rgba(..., 0)` 的透明区间——所以环不是「一整圈均匀的彩色」，而是**转起来时有一段亮、一段暗**，转一圈 4.2 秒。改这层的时候如果顺手加了 `overflow: hidden`，外扩的 1px 就被裁掉了，环会变成贴边的一条细线。

更隐蔽的是扫光的载体选择。彩环已经挂在 `::after` 上，按钮又必须 `overflow: visible` 才能露出向外扩 2px 的环。所以扫光只能走 `::before` 的背景位移，一旦为了「裁掉溢出」加上 `overflow: hidden`，彩环就被切掉了——**一个为了修 A 加的属性，悄悄弄坏了 B**。

这些都不是设计问题，但它们是「精心配置」的真实成本：**样式表里 1003 个 `!important`、77 处 `:not(#ah-never)` 特异性配重**，全是为了在别人的成品上做叠加而不失控。

## 所以「精心配置」到底指什么

回头看这七件事，没有一件是「调好看」。它们的共同结构是：

1. **先找到那个默认值为什么存在**——圆角、半透明、暂停动画，每一个都不是随便写的
2. **再判断这个理由在你的场景里还成不成立**——开关的圆形是语义，不能归零；页签的半透明是承诺，必须补模糊
3. **最后用可测量的方式确认**——边框量厚度、对比度量比值、动效看 `getAnimations()`，不靠肉眼

一个数字可以收尾：深色皮肤只有 **145 个色值**（其余全走 `--ah-*` 与 `--dsw-*` 令牌），浅色皮肤有 **390 个**。不是我给浅色偷懒——是因为浅色要覆盖的宿主默认样式更多，很多东西没法靠令牌推导，只能逐条钉死。

**令牌多的地方能改一处影响全站，硬编码多的地方只能一处一处对账。** 界面之所以看起来理所当然，是因为对账已经做完了。
